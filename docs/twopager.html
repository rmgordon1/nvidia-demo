Mission. The Bureau of Engraving and Printing (BEP) makes U.S. paper currency. BEP has two important operational problems. The IT systems in the plant must operate continuously. Inspectors must find press defects before a sheet goes to the next step. A small service desk finds solutions in many years of old tickets. At this time, the desk also moves from BMC Helix to ServiceNow. The inspection cameras use fixed rules. These rules reject good sheets, and they do not find new types of defects. BEP Operations AI gives agents and inspectors a second opinion that shows its sources. The system operates on one GB10. It does not send data outside the agency. A person makes each final decision.

ITSM Next Best Step

  • Retrieval: The system finds similar tickets in a synthetic Helix archive. It uses Nemotron embed, BM25, RRF fusion and Nemotron rerank.
  • Next steps: The system gives a ranked list of next steps. Each step shows its source tickets.
  • Routing: A classifier selects the support group. If the confidence is low, an LLM makes the decision.
  • Two tiers: gemma4 (Ollama) answers when the evidence is strong. gpt-oss-20b (vLLM) answers all other requests.
  • Other views: IT Self-Service removes PII. IT Insights changes questions into SQL.
USERS · IT support agent · employee · IT manager

Defect Inspection (CV)

  • Data: The press sheets are synthetic. They show fictional banknotes with 8 types of defects.
  • Stage 1: PatchCore learns only from good sheets. It gives each sheet a score and a heatmap. It also finds new types of defects.
  • Stage 2: RF-DETR-Seg identifies the defect type and shows its outline. Qwen3-VL-8B explanations are planned.
  • Human decision: QA makes the disposition for each sheet. QA sets the threshold and compares the result with the legacy rules.
  • Platform: MLflow records the training on site. A DeepStream and TensorRT line runtime is planned.
USERS · QA inspector · quality engineer

Governance & Audit

  • Audit trail: The system records each AI output and each human decision. Each record shows the user, action, decision and reason.
  • Provenance: Each AI output records the model, version, confidence and sources. ITSM records also show which tier answered and why.
  • Audit view: The administrator traces each decision to its input. The view exports the records to CSV.
  • Supply chain: All models have open weights. All versions are fixed. The SBOM lists them.
  • Advisory only: The system does not reject a sheet or close a ticket automatically.

Deploy. The command docker compose up -d --build starts four containers: webapp, rag, vllm and ollama. The first start downloads the open-weight models into Docker volumes. After the first start, the stack operates offline. It does not call external APIs.

Supply chain. The file requirements.txt fixes the version of each Python dependency. Each container image has a fixed tag. The file cv_model/artifacts.lock also records the digest of each CV image and weight file. The repository contains the gpt-oss tokenizer vocabulary. Thus, inference does not download files.
